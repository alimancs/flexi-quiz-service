# Flexi Quiz Service

Spring Boot REST API for managing topics, multiple-choice questions, exams, student attempts, results, leaderboards, and analytics.

## Running locally

- Java 17
- Maven
- PostgreSQL (connection properties are configured in `src/main/resources/application.properties`)

Run the application with:

```bash
mvn spring-boot:run
```

Run the existing tests with:

```bash
mvn test
```

Every controller route is prefixed with `/api/v1`. For example, the topic list is `GET /api/v1/topics`.

## Data model

The JPA entities are stored in the schemas/tables noted below. IDs are generated by the database.

```text
Topic 1 ── * MainQuestion 1 ── * MainQuestionOption
MainQuestion 1 ── * ExamQuestion * ── 1 Exam
Exam 1 ── * ExamAttempt * ── 1 Student
ExamAttempt 1 ── * AttemptAnswer * ── 1 MainQuestion
```

### `Topic`

Stored in `topic.topics`.

| Property | Type | Notes |
|---|---|---|
| `id` | `Long` | Generated primary key |
| `name` | `String` | Required and unique |
| `description` | `String` | Optional description |

### `MainQuestion`

Stored in `question.questions`. Each question belongs to one topic; it may have options and may be included in multiple exams.

| Property | Type | Notes |
|---|---|---|
| `id` | `Long` | Generated primary key |
| `topic` | `Topic` | Required relationship; omitted from JSON serialization on the entity |
| `text` | `String` | Question text |
| `difficulty` | `QuestionDifficulty` | Optional: `EASY`, `AVERAGE`, or `HARD` |
| `active` | `Boolean` | Nullable; exam question queries include active questions and questions where this is unset |
| `options` | `List<MainQuestionOption>` | Question choices |
| `created_at` | `Instant` | Set on insert |
| `updated_at` | `Instant` | Set on insert/update |

### `MainQuestionOption`

Stored in `questionoption.question_options`. Each option belongs to one question.

| Property | Type | Notes |
|---|---|---|
| `id` | `Long` | Generated primary key |
| `question` | `MainQuestion` | Required relationship; omitted from JSON serialization on the entity |
| `text` | `String` | Option text |
| `label` | `OptionLabel` | Required enum: `A`, `B`, `C`, or `D` |
| `is_correct` | `Boolean` | Indicates whether this option is correct; JSON property is `isCorrect` |

### `Exam`

Stored in `exam.exams`.

| Property | Type | Notes |
|---|---|---|
| `id` | `Long` | Generated primary key |
| `title` | `String` | Exam title |
| `duration_seconds` | `Integer` | Configured duration |
| `opens_at`, `closes_at` | `Instant` | Configured availability window |
| `max_attempts` | `Integer` | Configured attempt limit |
| `negative_marking` | `Boolean` | Negative-marking setting |
| `penalty_per_wrong` | `Integer` | Configured wrong-answer penalty |
| `status` | `ExamStatus` | `DRAFT`, `PUBLISHED`, or `CLOSED`; JSON property is `examStatus` |
| `created_by` | `String` | Creator identifier/name |
| `created_at` | `Instant` | Set on insert |
| `score_per_question` | `Integer` | Score used by current submission grading; defaults to `1` |

### `ExamQuestion`

Stored in `examquestion.exam_questions`; joins an exam to a question.

| Property | Type | Notes |
|---|---|---|
| `id` | `Long` | Generated primary key |
| `exam` | `Exam` | Required relationship; omitted from JSON serialization on the entity |
| `question` | `MainQuestion` | Required relationship; omitted from JSON serialization on the entity |
| `position` | `Integer` | Assigned as the next position when added |
| `marks` | `Integer` | Defaults to `1`; current submission grading uses the exam's `score_per_question` instead |

### `Student`

Stored in `student.students`.

| Property | Type | Notes |
|---|---|---|
| `id` | `Long` | Generated primary key |
| `fullname` | `String` | Student's full name |
| `email` | `String` | Required and unique |
| `password` | `String` | Password field; student endpoints currently return the entity directly |

### `Teacher`

Stored in `teacher.teachers`. No teacher-specific REST endpoints are currently defined.

| Property | Type | Notes |
|---|---|---|
| `id` | `Long` | Generated primary key |
| `fullname` | `String` | Teacher's full name |
| `department` | `String` | Department |

### `ExamAttempt`

Stored in `attempt.attempts`. Each attempt references one exam and one student; the relationships are ignored in entity JSON serialization. The token hash has a `tokenHash` getter and is not ignored.

| Property | Type | Notes |
|---|---|---|
| `id` | `Long` | Generated primary key |
| `exam`, `student` | Relationships | Required |
| `token_hash` | `String` | Unique token hash; JSON property is `tokenHash` |
| `status` | `AttemptStatus` | `IN_PROGRESS`, `SUBMITTED`, or `EXPIRED`; defaults to `IN_PROGRESS` |
| `started_at`, `expires_at` | `Instant` | Start and expiry timestamps |
| `submitted_at`, `updated_at` | `Instant` | Submission/update timestamps |
| `score` | `Integer` | Defaults to `0` |
| `correct_count`, `wrong_count`, `unanswered_count` | `Integer` | Result counters; default to `0` |

### `AttemptAnswer`

Stored in `attemptanswer.attempt_answers`. A database unique constraint allows at most one answer for each attempt/question pair.

| Property | Type | Notes |
|---|---|---|
| `id` | `Long` | Generated primary key |
| `attempt` | `ExamAttempt` | Required relationship; omitted from JSON serialization on the entity |
| `question` | `MainQuestion` | Required relationship; omitted from JSON serialization on the entity |
| `selected_option` | `MainQuestionOption` | Required relationship; omitted from JSON serialization on the entity |
| `is_correct` | `Boolean` | Correctness of the selected option |
| `marks_awarded` | `Integer` | Marks recorded for the answer |

## API

The API currently has no authentication/authorization layer wired into these controllers. Route group labels below describe intended use, not enforced roles.

### Topics

| Method and path | Description | Request body / query |
|---|---|---|
| `GET /api/v1/topics` | List all topics as `{ "topics": [...] }` | — |
| `POST /api/v1/topics` | Create a topic; returns `{ "topic": ... }` | `{"name":"Algebra","description":"Equations and expressions"}` |
| `PUT /api/v1/topics/{id}/name` | Rename a topic | `{"newName":"Geometry"}` |
| `PUT /api/v1/topics/{id}/desc` | Update a topic description | `{"newDesc":"Shapes and measurement"}` |

The topic update routes return `400` for a missing/empty update value and `404` when the topic ID is not found.

### Questions

| Method and path | Description | Request body / query |
|---|---|---|
| `GET /api/v1/questions?topicId={id}` | Return a page of questions for a topic | Optional `q`, `page` (default `0`), and `size` (default `5`) |
| `GET /api/v1/questions/{id}` | Get a question by ID | — |
| `POST /api/v1/questions` | Create a question from the supplied question text and topic relationship | Entity-shaped JSON, e.g. `{"text":"What is 2 + 2?","topic":{"id":1}}` |
| `PUT /api/v1/questions/{id}` | Replace the question text | JSON string, e.g. `"Updated question text"` |
| `DELETE /api/v1/questions/{id}` | Delete a question | — |

Question listing sorts by ID descending. When `q` is supplied, the current repository method matches the question text by equality (not substring/full-text search). The page response uses Spring Data's `Page` JSON structure. Question creation does not create choices; the exam question endpoint below accepts question options.

### Exams

| Method and path | Description | Request body |
|---|---|---|
| `GET /api/v1/exams` | List all exams | — |
| `GET /api/v1/exams/{id}` | Get an exam by ID | — |
| `POST /api/v1/exams` | Create an exam; returns `201 Created` and the saved entity | Exam entity fields, for example `{"title":"Quiz 1","durationSeconds":3600,"opensAt":"2026-11-16T09:00:00Z","closesAt":"2026-11-16T10:00:00Z","maxAttempts":1,"negativeMarking":false,"penaltyPerWrong":0,"examStatus":"DRAFT","createdBy":"teacher-1","scorePerQuestion":1}` |
| `PUT /api/v1/exams/{examId}/questions` | Add one question and its options to an exam; returns the exam-question DTO | `{"question":{"text":"What is 2 + 2?","topic":{"id":1},"difficulty":"EASY"},"options":[{"text":"3","label":"A","isCorrect":false},{"text":"4","label":"B","isCorrect":true}]}` |
| `POST /api/v1/exams/{id}/publish` | Set the exam status to `PUBLISHED` | — |
| `DELETE /api/v1/exams/{id}` | Delete an exam | — |

Adding a question assigns the next position and returns a `QuestionForExamDto` with `examQuestionId`, `questionId`, `text`, `difficulty`, `position`, `marks`, and options. In the current DTO mapping, the values for `examQuestionId` and `questionId` are reversed: the question ID is returned as `examQuestionId`, and the join-row ID is returned as `questionId`. Option payloads use `text`, `label`, and `isCorrect`; options returned to students use `id`, `label`, and `text`, omitting correctness.

### Attempts

| Method and path | Description | Request body |
|---|---|---|
| `POST /api/v1/exams/{examId}/attempts` | Request an attempt and the exam questions | `{"studentId":123}` |
| `GET /api/v1/attempts/{id}` | Get an attempt entity | — |
| `PUT /api/v1/attempts/{id}/answers` | Save selected options for questions; returns an `invalidAnswers` array | `{"answers":[{"questionId":10,"selectedOptionId":42}]}` |
| `POST /api/v1/attempts/{id}/submit` | Save the provided answers, grade the attempt, and return `{ "invalidAnswers": [...], "result": ... }` | `{"answers":[{"questionId":10,"selectedOptionId":42}]}` |
| `GET /api/v1/attempts/{id}/result` | Return the attempt result and answer/option breakdown | — |
| `GET /api/v1/attempts/{id}/analytics/topics` | Return one attempt's breakdown grouped by topics represented in its saved answers | — |

The attempt response is intended to contain an attempt ID, a raw token, an expiry time, and student-safe question DTOs. **Current implementation caveat:** the start-attempt handler constructs an attempt but does not save it before forming its response. Since the generated ID is still `null` and `Map.of` rejects null values, the response construction fails; the response key is also misspelled `attempId`. Do not rely on this route to start a usable attempt until these issues are corrected.

Answer saving and submission currently accept `questionId` and `selectedOptionId` pairs. Invalid question/option IDs are returned in `invalidAnswers`; an empty `answers` list returns `400`. Current grading awards `exam.score_per_question` for each correct answer, counts incorrect answers, and computes unanswered count from the exam's question count. Although the exam model has negative-marking and per-question marks settings, those settings are not applied by this grading implementation.

The result includes the exam, a student summary (`fullname`, `email`), answers, status, timestamps, score, and correct/wrong/unanswered counts. Each answer includes the question text, mark, selected option, and option list. The attempt analytics response includes the same attempt summary plus topic name/description, answer breakdown, correct/wrong counts, and total recorded marks per topic.

**Important security note:** the controllers do not verify an attempt token or bind answer operations to an authenticated student. `Student` entities include a password property and are returned directly by student endpoints. `ExamAttempt` responses also expose `tokenHash`. Protect these endpoints and avoid exposing passwords or token hashes before using this API with real accounts.

### Students

| Method and path | Description | Request body |
|---|---|---|
| `GET /api/v1/students/{id}` | Get a student, wrapped as `{ "student": ... }` | — |
| `GET /api/v1/students/{id}/attempts` | Get a student's attempts, wrapped as `{ "attempts": [...] }` | — |
| `POST /api/v1/students` | Create a student, wrapped as `{ "student": ... }` | `{"fullname":"Alex Example","email":"alex@example.com","password":"..."}` |

### Leaderboard and exam analytics

| Method and path | Description |
|---|---|
| `GET /api/v1/exams/{id}/leaderboard` | Return `{ "positions": [...] }`, ordered by score descending. Each position contains student name/email, score, and position. |
| `GET /api/v1/exams/{id}/analytics/topics` | Return exam-wide attempt counts, score statistics, and per-topic performance. Only submitted attempts contribute to score/topic statistics. |

The exam analytics response has this shape:

```json
{
  "examId": 12,
  "title": "Quiz 1",
  "attempts": {
    "total": 10,
    "completed": 7,
    "inProgress": 2,
    "expired": 1
  },
  "scores": {
    "average": 7.5,
    "median": 8.0,
    "highest": 10,
    "lowest": 4,
    "averagePercent": 75.0
  },
  "topics": [
    {
      "topicId": 3,
      "name": "Algebra",
      "questions": 4,
      "answered": 25,
      "correct": 18,
      "incorrect": 7,
      "unanswered": 3,
      "accuracyPercent": 72.0,
      "averageMarksPercent": 72.0
    }
  ]
}
```

Score values are in points; percentages are rounded to one decimal place. Score statistics are `null` when there are no submitted attempts. Topic accuracy is based on answered questions, while `unanswered` counts missing answers across submitted attempts. Analytics currently assumes the exam's configured `score_per_question` applies equally to every question.

## Enum values

- `ExamStatus`: `DRAFT`, `PUBLISHED`, `CLOSED`
- `AttemptStatus`: `IN_PROGRESS`, `SUBMITTED`, `EXPIRED`
- `QuestionDifficulty`: `EASY`, `AVERAGE`, `HARD`
- `OptionLabel`: `A`, `B`, `C`, `D`

## Current implementation notes

- The documented request/response behavior reflects the current controllers and DTOs; it is not a statement that all routes are production-ready.
- Several routes throw runtime exceptions for missing entities rather than using a consistent API error format.
- The codebase currently does not enforce the proposed role-based access, attempt limits, exam availability windows, or token validation in controller handlers.
- `ExamQuestion.marks`, `Exam.negative_marking`, and `Exam.penalty_per_wrong` are represented in the model, but are not used in current submission scoring.
- Database uniqueness currently exists for topic names, student emails, attempt token hashes, and the `(attempt_id, question_id)` answer pair. The service does not enforce exactly one correct option per question.
